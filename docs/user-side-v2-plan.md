# 用户端 V2 实施计划

**目标：**让现有 PWA 在单一工作界面支持每日记录、可解释的动态状态分、应用内变化提醒与跨天回访。

**架构：**现有 JSON 填充固定日期的模拟设备读数；本机记录按日期和字段覆盖样例，向派生函数与判断层传入合并后的记录及来源。分数用纯函数计算，提醒复用信号与安全层。页面消费视图模型，四个一级入口不变。

**技术：**React 19、TypeScript、Vite、localStorage；无新增依赖或后台。

**设计：**`docs/user-side-v2-design.md`

**当前状态（2026-09-26）：**已统一首页、小满、健康方案和我的的数据流；健康记录移入“我的”。按日合并模拟读数与用户实际填写字段，显示来源；首页补今日观察和 7 天趋势，只有本人字段触发个人回访。小满演示读取本机数据并展示变化依据，仅对明确的产品咨询意图显示方案入口；健康方案可浏览非药品模拟项目并走通本机演示订单，安全升级时暂停展示和下单。完整 Trace、真实设备、真实商城交易、关闭应用后的提醒和专业后台仍待后续阶段。

**用户反馈调整：**不再提供模拟/本人两套 UI 或切换按钮。静息心率与血压由模拟设备数据展示但不进入状态分；设备同步和真实模型仍需后续权限与验证。

## 全局约束

- 模拟读数按固定本机日期映射，并逐字段标注来源；不把模拟值写成用户输入或真实测量。
- 分数是生活状态反馈，不能写成疾病风险或诊断；安全升级始终高于分数。
- 新判断只写在 `src/ai/` 或纯派生函数，页面不复制阈值。
- 沿用现有组件、状态和样式；不新增依赖。
- `npm run build` 与 `npm run eval` 必须通过；行为变化更新 AI 版本与模型卡。

## 重点复核的输入

- 用户只填一项：仅该字段写进本机记录，其余模拟值继续明确标注来源。
- 跨午夜和刷新：当天日期、记录归属、行动状态均保持正确。
- 同一信号多次重算：只有一个持续事项，不反复提醒。
- 用户修改旧记录：历史分数与受影响的趋势重算，旧事件保留原始证据快照。
- 急症文本与普通生活变化同时出现：升级路径优先，普通行动停用。
