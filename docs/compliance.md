# 合规与风险登记

> 这不是法律意见。这是一个产品负责人应该在写第一行代码之前就摆到桌面上的清单：
> 我们在什么边界内、数据怎么处理、出错时谁兜底。

## 一、产品定位与法规边界

| 项 | 结论 |
| --- | --- |
| 产品定位 | 健康**管理**工具（生活方式建议 + 健康知识解释），不是医疗器械 |
| 是否宣称医疗器械 | **否**。不做 SaMD/NMPA 器械宣称，不进入诊断、治疗、用药决策链路 |
| 允许的输出 | 生活方式建议、健康知识解释、风险提示、建议就医（四级，见「数据与安全」页） |
| 明确不做 | 疾病诊断、开具处方、治疗决策、替代急症判断、个体风险评分 |
| 边界的产品化 | 四级输出分级 + 急症优先规则 + 升级流程，均已实现并有评测守卫（`npm run eval`） |

如果未来要做诊断辅助，路径不是加功能，而是重新走器械注册评估——这是两条不同的产品线，不能靠迭代悄悄跨过去。

## 二、个人信息与数据

| 项 | 现状 | 说明 |
| --- | --- | --- |
| 数据类型 | 健康数据属于**敏感个人信息**（个保法第 28 条） | 睡眠、活动、情绪、既往史、家族史都在此列 |
| 当前实现 | 本人每日记录、目标、跟进事项保存在浏览器本机（`localStorage`），无后端、无上报 | 演示数据另作独立来源；清除浏览器数据会丢失本人记录 |
| 同意设计 | 首次进入需明示「演示数据、非医疗服务」，升级类回答自带边界说明 | 单独同意、撤回路径**尚未实现** |
| 最小化 | 埋点方案明确不带健康数值原文（见 `docs/metrics.md`） | 待落地上报时执行 |
| 跨境与共享 | 未接入任何第三方分析或广告 SDK | 接入 LLM 时会产生数据出境/委托处理问题，见下 |

**接入 LLM 时的三个前置动作**（当前未做，写在这里是为了不做隐形决定）：

1. 明确告知用户哪些内容会发送给模型服务商，并取得单独同意；
2. 与服务商签订数据处理协议，关闭用于训练的选项；
3. 传输前做字段级脱敏（去掉姓名、精确日期，只保留必要的结构化数值与信号）。

**架构上的额外要求**：模型调用不应从浏览器直连——那会暴露 API key，也无法做服务端审计与限流。本项目已经预留了 `transport` 接缝（`src/ai/transport.ts`），真实部署时应替换为「客户端 → 本服务（BFF）→ 模型服务」，由服务端负责鉴权、脱敏、日志与配额。

## 二之二、边界在系统里的落点

合规要求不能只写在文档里，必须落到代码结构上。本项目的落点是**守门层**（`src/ai/guardrails.ts`）：

| 合规要求 | 系统落点 |
| --- | --- |
| 不做诊断、不给用药建议 | 守门层禁区断言（断言型正则）+ 统一转介文案；药物相关提问在生成层就保守转介 |
| 急症必须转介 | 生成层与守门层**共用同一份**急症规则（`src/ai/safety.ts`），且优先级高于所有可建议话题 |
| 建议必须有依据 | 守门层要求 evidence 非空，缺失即用当日信号补齐；无依据可用则降级 |
| 不过度干预 | 守门层限制单日行动 ≤ 4 条（结构性约束，不依赖提示词自觉） |
| 输出可解释 | 每次判断输出 Trace（阶段、信号阈值、召回记忆、守门判定），界面上是「判断过程」面板 |
| 模型不可靠时仍要安全 | 降级路径：模型失败回退规则实现；致命违规**整体替换**（fail-closed） |

这套强制层的有效性由 `eval/guardrail-cases.json` 守卫（10 条越界/畸形输出，不需要 API key）。

## 三、审计与可追溯

医疗场景下「当时为什么这么建议」必须能回溯。设计方案：

| 对象 | 版本化方式 | 回溯能力 |
| --- | --- | --- |
| 知识条目 | 每个 `.md` 带来源、复核状态、更新日期 | 建议可指向具体条目与版本 |
| 规则表 | 规则 id 稳定（如 `red-flag:medication`），改动进 ADR | 可复现某天的判断逻辑 |
| 会话与建议 | 记忆条目带日期与来源 | 当前存本机；上后端后需不可篡改的审计日志 |
| 评测 | 用例集带版本号，失败明细保留 | 可对比模型/规则变更前后的行为 |

缺口：现在**没有**服务端审计日志，用户清除浏览器数据即丢失。这在演示阶段可接受，在真实医疗场景不可接受。

## 四、人工复核（Human-in-the-loop）

知识条目的「待医学复核」目前只是一个标记，完整流程设计如下：

```
草稿 ──► 待医学复核 ──► 已复核 ──► 过期（超过复核周期）
           │
           └──► 驳回（附原因，回到草稿）
```

| 环节 | 角色 | 规则 |
| --- | --- | --- |
| 提交复核 | 产品 / 知识运营 | 必须填写来源与适用范围 |
| 医学复核 | 具备资质的医学人员 | 可驳回；驳回原因必须留痕 |
| 发布 | 系统 | 只有「已复核」状态可被规则引用 |
| 过期 | 系统 | 超过复核周期自动降级为「待复核」，不再被引用 |

**当前实现程度**：状态字段与展示已实现（知识管理页），流转、权限、过期策略**未实现**。规则引用未复核条目的情况在评测里可被检查，属于下一步。

## 五、风险登记表

| # | 风险 | 场景 | 影响 | 可能性 | 缓解措施 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| R1 | 幻觉式医疗建议 | LLM 给出知识条目外的断言 | 高 | 中 | 只允许引用已复核条目；接 LLM 后强制引用 id；人工抽检 | 部分（规则桩无幻觉，守卫已就位） |
| R2 | **漏报急症**（最高风险） | 用户描述胸痛但系统给生活方式建议 | 极高 | 中 | 急症优先规则 + 评测 C 类；E-04 英文胸痛已纳入回归 | 部分（6 类与少量英文胸痛表达，其他外语仍可能漏报） |
| R3 | 越界诊断 | 用户问「我这是什么病」，系统给结论 | 极高 | 低 | 断言型禁区正则 + 评测 B 类 | 已缓解 |
| R4 | 用药建议 | 询问药物名称/剂量 | 极高 | 中 | 药物提问一律转介（最宽匹配） | 已缓解（ADR-0010） |
| R5 | 过度干预引发焦虑 | 一天多次主动提示异常 | 中 | 中 | 单日打扰上限、「没有明显感觉」不新增任务 | 部分（产品约束已有，指标未埋点） |
| R6 | 敏感数据泄露 | 健康数据被第三方获取 | 高 | 低 | 本机处理、埋点最小化、接 LLM 前三项前置动作 | 部分 |
| R7 | 建议照搬人群标准 | 忽略个人基线，判读不一致 | 中 | 中 | 四层判断结构（人群 + 个人 + 趋势 + 事件） | 已缓解 |
| R8 | 用户依赖替代就医 | 把助手当成医生 | 高 | 中 | 分级输出 + 升级流程 + 每次升级的明确路径 | 部分 |

R2 与 R4 是仅有的两个「单次即事故」风险，因此它们的阈值是 0，而不是「小于某个比例」。

## 六、明确没做的事（以及为什么）

| 未做 | 原因 |
| --- | --- |
| 真实器械注册与合规审查 | 超出作品集范围；产品定位也不越界到器械 |
| 数据加密存储与访问控制 | 当前无服务端；上后端时必须补，属于 P0 |
| 第三方安全审计 | 同上 |
| 用户协议与隐私政策的正式文本 | 需要法务；当前用页面声明替代 |
| 未成年人保护流程 | 目标用户为成年人，若扩展需单独设计 |
