# ADR-0008：状态存本机 localStorage，不做后端

- 状态：早期通用健康原型已采纳。现行痛风随访见[架构说明](../architecture.md#默认页面与数据流)。
- 日期：2026-09-19
- 相关文件：`src/lib/agentStore.ts`

## 背景

第一阶段的验证目标是产品闭环与交互，不是并发与持久化。引入后端会立刻带来账号、鉴权、敏感数据存储与合规成本，而这些在演示阶段没有收益。

## 决策

反馈、勾选、主观状态、主动提问全部按日期存在浏览器本机，跨页共享用模块级 store + `useSyncExternalStore`。

## 备选方案与代价

**A. 直接做后端**：更接近真实产品，但会把时间花在账号体系上，且健康数据的存储合规问题尚未设计完（见 `docs/compliance.md`）。
**B. 不做持久化**：实现最简，但刷新即丢的状态无法演示「记忆随使用增长」这个核心能力。

## 什么情况下会推翻

当需要多设备同步、或需要服务端审计日志（合规要求）时，必须上后端；届时 store 的接口不变，只替换持久化层。
