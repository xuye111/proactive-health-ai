# ADR-0004：第一版用规则桩，先建评测再接 LLM

- 状态：已采纳
- 日期：2026-09-19
- 相关文件：`eval/`（判断实现于 ADR-0011 分层重构后迁至 `src/ai/providers/rules.ts`）

## 背景

直接接 LLM 会让「判断是否正确」变成不可复现的黑盒，也会把医疗边界问题推给提示词。而在作品集与真实项目里，AI 产品经理的核心产出之一恰恰是**评测标准**。

## 决策

第一版用一张确定的规则表实现判断与回答，同时建立可运行的评测集（首批 25 条用例，当前规模与结果见 `docs/eval.md`）。评测集与实现解耦：换成 LLM 后断言不变。

## 备选方案与代价

**A. 先接 LLM，后补评测**：演示效果更好，但没有判据就没有选型依据，也无法回答「误报漏报多少」。
**B. 只做静态原型，不写规则**：省时间，但无法验证闭环是否真的成立（例如反馈是否真的改变了行动）。

## 什么情况下会推翻

当评测集的新增失败主要集中在「语义表达未覆盖」（E 类）而不是「规则写错」时，就该换实现了。
