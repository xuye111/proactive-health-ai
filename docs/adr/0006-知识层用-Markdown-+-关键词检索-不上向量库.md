# ADR-0006：知识层用 Markdown + 关键词检索，不上向量库

- 状态：已采纳
- 日期：2026-09-19
- 相关文件：`src/lib/knowledge.ts, src/data/knowledge/`

## 背景

方案 §16 的第一版形态就是 Markdown + 关键词检索。知识条目只有 4 个、总量很小，向量库在这个规模下带来的是复杂度而不是效果，而且会掩盖真正的瓶颈：内容是否经医学复核。

## 决策

知识就是 Markdown 文件（含来源、复核状态、五个固定段落），检索用关键词，条目详情在「知识管理」页可查。

## 备选方案与代价

**A. 直接上 RAG**：技术上更「完整」，但 4 个条目的语料规模下检索质量差异不可测，却引入了 embedding 依赖与版本管理成本。
**B. 不做知识层，让模型自由回答**：等于放弃「建议可指向来源」这个可信度基础。

## 什么情况下会推翻

知识条目超过约 30 个、或用户提问的关键词命中率低于 60% 时，升级为切片 + 向量检索。
