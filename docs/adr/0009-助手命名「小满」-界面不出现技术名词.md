# ADR-0009：助手命名「小满」，界面不出现技术名词

- 状态：早期通用健康原型已采纳。现行痛风随访见[架构说明](../architecture.md#默认页面与数据流)。
- 日期：2026-09-19
- 相关文件：`src/lib/assistant.ts`

## 背景

用户面对的是一个具体的助手，而不是一个技术名词。持续在界面上出现「AI」，会让产品气质偏向工具，也会让人误以为它具备通用智能（进而问出它答不了的问题，抬高兜底率）。同时，名字不能让人误以为能看病。

## 决策

定名「小满」（节气名，取「小满即安」，寓意刚刚好、不过度，与「只给生活方式建议、不越界」的定位同构）。界面文案一律用名字；名称集中在一处常量，文档与技术说明中仍保留 AI/LLM 等准确术语。

## 备选方案与代价

**A. 叫「小安」「健康助手」**：直白好记，但前者容易被理解为安全/医疗，抬高错误预期。
**B. 不命名，统一叫 AI**：省事，但放弃了产品人格化与预期管理这两个作用。

## 什么情况下会推翻

当用户访谈显示名字被理解为「真人医生」时（预期管理失败），需要更明确地标注它的边界。
